[Conclusion]
We have the root cause regardless of how this test comes out:

  [    0.085388] pci_bus 0005:02: extended config space not accessible
  [    0.093913] pci_bus 0005:82: extended config space not accessible

  The full chain, each link now evidence-backed:

  1. At enumeration, pci_bridge_child_ext_cfg_accessible(0005:01:00.0) returned false
  2. → PCI_BUS_FLAGS_NO_EXTCFG set on buses 0005:02 and 0005:82
  3. → pci_cfg_space_size() returns 256 without probing (early-out at probe.c:1789)
  4. → lspci/sysfs truncate at 256 → no extended caps visible
  5. → pci_find_ext_capability(ATS) finds nothing → pci_enable_ats() never called
  6. → STE.EATS = 0 → every ATS request → F_BAD_ATS_TREQ (event 0x05)

The causal chain is established and reproducible:

  Linux flags bus 0005:02/0005:82 "extended config space not accessible"
    → PCI_BUS_FLAGS_NO_EXTCFG
    → pci_cfg_space_size() returns 256 without probing
    → extended caps never enumerated (ATS at 0x3a8 invisible)
    → pci_enable_ats() never called → STE.EATS = 0
    → GPU's ATS requests → F_BAD_ATS_TREQ (event 0x05)
